# Contribuer à Un pas après l'autre

Tu peux retrouver son travail sur [Un pas après l'autre](https://unpasapreslautre.fr/).

## Signaler un bug

[🐛 Signaler un bug](https://github.com/JLEGAC/onestepafteranother/issues/new?template=bug.yml)

Pour m'aider à reproduire le problème, indique :

- La version de l'application, si tu la connais.
- Ton appareil, ton système et ton navigateur. Précise si l'application était installée ou ouverte dans un onglet.
- Les étapes à suivre, ce que tu attendais et ce qui s'est passé.
- Si le problème concerne une sauvegarde ou une restauration, le mode utilisé : local, Dropbox ou Supabase.

Une capture anonymisée peut aider. Les tickets GitHub sont publics : ne joins pas de sauvegarde personnelle, de jeton ni de capture qui montre tes données.

## Proposer une amélioration

[💡 Proposer une amélioration](https://github.com/JLEGAC/onestepafteranother/issues/new?template=enhancement.yml)

Décris le besoin avec un exemple : qu'essayais-tu de faire, qu'est-ce qui te gêne aujourd'hui et qu'est-ce qui te faciliterait la tâche ? Tu peux proposer une solution si tu en as une. Un retour sur un parcours suffit déjà à faire avancer le projet.

## Proposer une modification du code

1. Pour un changement important, ouvre d'abord un ticket pour en discuter.
2. Crée une branche dédiée et suis les [instructions de développement](README.md#développement-local).
3. Lance `npm run check`, `npm test` et `npm run build`. Si la modification touche un parcours dans l'interface, vérifie-le aussi dans le navigateur, sur un écran étroit si pertinent.
4. Dans ta pull request, explique ce qui change, pourquoi et comment tu l'as vérifié. Ajoute une capture si elle rend le changement plus facile à comprendre.

Merci pour tes retours et tes contributions !
